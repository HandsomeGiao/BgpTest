# 跳过未要求的测试

## 应用规则

- 将本规则应用于每个修改代码或代码相关文件的任务。
- 除非用户明确要求测试，否则不要运行任何测试。
- 不要因为用户要求实现、修复、重构、完成或以其他方式修改代码，就推断用户允许进行测试。
- 如果测试权限含糊不清，直接跳过测试；不要仅为了遵循常规验证流程而询问是否可以测试。

## 将验证视为测试

- 跳过单元测试、集成测试、端到端测试、回归测试、冒烟测试、属性测试、逻辑测试以及类似的自动化测试。
- 跳过手动或自动界面测试、基于浏览器的验证，以及仅为检查行为而启动应用程序。
- 跳过测试脚本，以及仅为验证正确性而执行代码的行为。
- 当构建、编译、代码检查、类型检查或静态分析的目的是验证代码修改时，跳过这些操作。仅在用户明确要求，或生成用户要求的交付物必须执行时运行它们。
- 除非用户明确要求测试，否则不要仅为验证修改而创建或修改测试代码。

## 在不测试的情况下完成工作

- 仅通过检查源文件和最终差异来确认修改内容及其范围；不要把这种检查描述为代码能够正常工作的证明。
- 在最终回复中说明由于用户没有要求，因此未运行测试。
- 不得声称未执行的测试已经通过，也不得声称未经测试的行为已经得到验证。

## 处理明确的测试请求

- 将用户直接要求测试、指定测试命令或指定测试范围视为测试授权。
- 仅运行用户要求或为完成该明确测试请求所必需的测试范围。
- 如实报告运行的命令及其结果。
